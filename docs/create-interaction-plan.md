# Compose Foundation Create 页面与组件交互目标

## Goal

完成 `/create` 的配置、实时预览和预设导入导出流程，使其与 shadcn Create 的关键行为对齐。修复组件在鼠标、键盘、触屏和混合输入设备上可复现的交互问题，优先解决取消后误触发、横向手势阻断页面滚动和弹层焦点丢失。沿用 Compose Foundation 的主题、预设模型与组件 API。

以 [shadcn Create](https://ui.shadcn.com/create) 和[官方主题说明](https://ui.shadcn.com/docs/theming)为外部参考。浏览器和截图验收沿用[现有 Web 对齐标准](shadcn-web-plan.md)。实际发现、验证证据、提交和阻塞项记在[实施进度](create-interaction-progress.md)。

## 第一阶段 · Create 页面

| 顺序 | 工作 | 验收 |
| --- | --- | --- |
| 1 | 固定参考日期、上游源码版本和本地提交。从 `CreatePage.kt`、`CreateCustomizer` 和 `CreatePreviewCanvas` 核对布局、配置、欢迎弹层、命令面板和导出入口。 | 建立逐项对照，写明预期行为、当前差异和验证场景。 |
| 2 | 完善桌面配置侧栏、窄屏底部配置区和预览滚动。 | 桌面、平板和手机均可访问配置与预览。跨断点和横竖屏切换保留当前配置与预览选择。 |
| 3 | 核对样式、颜色、圆角、字体和图标选项。复用已有主题 token 和预设模型，让页面、快捷操作和导出读取同一配置。 | 修改配置后预览即时更新。浅色和深色均能正确反映选项，导出值与当前配置一致。 |
| 4 | 接通 `Preview 01/02`、`Shuffle`、`Reset`、`Open Preset` 和 `Get Code`。 | 每个入口完成对应操作。导出的预设可重新打开并恢复设置，无效预设给出清晰反馈。 |

## 第二阶段 · 组件交互

| 优先级 | 范围 | 验收 |
| --- | --- | --- |
| P0 | 指针生命周期 | 核对按下、移出、抬起、取消及交互途中禁用。取消或转入滚动时不会误触发点击，结束后清理按压状态。 |
| P0 | 滑动与拖拽 | 优先检查 Slider、Carousel、Sheet 和 ScrollArea。按组件行为验证方向判定、阈值、嵌套滚动、边界和 RTL。横向手势区域内仍可纵向滚动页面。 |
| P1 | Hover 与触屏入口 | 优先检查 Tooltip、Hover Card、DropdownMenu 和 NavigationMenu。验证鼠标进入与离开、触屏点按或长按，以及混合设备按实际输入切换时无残留状态。 |
| P1 | 键盘与无障碍 | 按组件语义验证 Tab、方向键、Enter、Space 和 Escape，以及焦点可见、弹层焦点恢复、可访问名称、禁用和选中状态。 |

在现有示例中复现后修复组件本身。`/create` 暴露的通用问题也归入对应组件处理。只有输入判定、事件消费和取消语义一致时才共享实现。

## 完成条件

- 桌面和手机均通过「打开页面 → 修改配置 → 切换预览 → 导出 → 重新打开」流程。断点切换和浅深主题有截图与交互证据。
- 交互表中的适用场景逐项复核。确认的缺陷有修复前复现、修复后通过和对应提交。确有依据保留的差异有明确理由。
- 受影响模块的 JVM 回归、`ktlintCheck` 和 Detekt 通过。涉及视觉变化的场景按[视觉测试说明](visual-testing.md)补快照。JS 与 Wasm 均在真实浏览器验证，滑动与页面滚动冲突还需在真实触屏设备复核。
- 按 Create 布局、配置与操作及各组件交互提交。实施进度可追溯到参考基线、文件位置、验证结果和提交。缺失的必验场景继续保持待验证。
