# Compose Foundation 代码审查与清理目标

## Goal

以 `95c932b6` 为审查基线，完成两轮组件与 Web 适配的代码审查。修复已确认且可修复的行为缺陷，清理无依据的硬编码、职责混杂、行为重复的实现和已确认无引用的私有代码。保留公开 API、默认行为、主题差异和用户已有的工作区改动。按组件提交修复，并为每项发现留下文件位置、影响、处理结果和可复核的验证证据。

实际发现、提交、验证结果和受阻事项记在[代码审查进度](code-review-progress.md)。Detekt 存量规则的分批清理见[独立计划](detekt-cleanup-plan.md)。

## 审查范围

| 顺序 | 范围 | 审查重点 |
| --- | --- | --- |
| 第一轮 | `:shadcn:core` 的 Select、Toast、共享弹层及其 Web 适配 | 从 `Select.kt`、`NovaToastViewport.kt`、`AnchoredPopup.kt` 入手，检查弹层几何、状态写入、计时器、关闭顺序、焦点恢复和监听器生命周期。 |
| 第二轮 | Slider、Sheet、Toggle，以及目录应用的浏览器滚动和导航 | 检查拖动和取消、键盘与触摸切换、RTL、无障碍语义、滚动宿主和浏览器前进后退。 |

每轮先复现状态覆盖、监听泄漏、焦点丢失和无障碍回归，再处理结构问题。核对候选文件中的本地改动。遇到重叠时记录具体文件和依赖，继续完成独立范围；待相关改动整合后复审受阻项。

## 全组件扩展

前两轮的范围及结论继续有效。后续逐一审查 `:shadcn:core` 的全部 67 个组件源码包，包含 AI Elements。按实际源码目录核对清单，并纳入同名平台实现、共享层调用、目录示例和相关测试。跨组件的风险在相应的消费方和实现方一并核对。

先处理可复现的交互缺陷和更容易影响多处调用的组件。以[逐组件进度](code-review-progress.md#全组件扩展进度)登记人工审查和 Detekt 清理两项状态，引用已覆盖的验证证据。组件只有在两项状态均验收后才算完成。新增或改名的源码包同步更新清单。

## 修复准则

- 视觉值优先复用现有主题 token。行为阈值使用能表达用途和单位的名称。窗口尺寸、密度、布局方向和平台能力从运行时读取，核对 dp、窗口像素和 CSS 像素之间的转换。
- 来源明确的组件常量、查找表、示例数据和测试期望值可以保留，记录对应依据。生成示例从源文件修改。涉及 Toggle 示例时运行 `python3 scripts/generate_toggle_recipe_code.py --check`。
- 明确状态所有者和副作用的生命周期。提取可独立验证的几何计算和决策逻辑。关闭顺序、事件消费、取消和焦点行为一致时才合并实现。
- 保持 Detekt 的现有规则阈值，由 ktlint 检查格式。修复存量告警时用前后扫描证明问题已消失，再删除对应 baseline ID。

## 完成条件

- [ ] 两轮列出的组件和平台路径均已审查，每项发现都有文件位置、影响、处理结果和证据。
- [ ] 已确认且可修复的缺陷均有组件提交。每项行为修复都证明原实现可复现、修复后通过。结构清理通过受影响的现有回归测试。
- [ ] 相关 JVM 回归、`ktlintCheck` 和实际扫描 Kotlin 源码的 `detekt` 均已验证。涉及视觉、布局或动画的改动按[视觉测试说明](visual-testing.md)核对快照。涉及 Web 交互的改动构建受影响的 JS/Wasm 目标，并在真实浏览器验证相关行为。
- [ ] 公开 API、默认行为、主题差异及已有工作区改动得到保留。交付记录列出修复提交、保留理由、改动前已有的失败，以及仍受阻的事项和解除条件。

核对当前源码、提交及测试结果后判定完成。缺少证据的范围继续保留为待验证。仍受阻的必做项继续跟踪，直至可以修复并验收。

第一轮从以下 JVM 和静态检查入口开始，随后按实际改动扩大验证范围。

```sh
./gradlew :shadcn:core:jvmTest --tests '*SelectPopupGrowth*Test' \
  --tests '*ToastManagerParityTest' --tests '*ToastBehaviorParityTest'
./gradlew :shadcn:core:ktlintCheck :shadcn:core:detekt
```
