# Detekt 存量告警清理计划

## 基线与目标

以 `0989319b` 的已提交源码为起点。Detekt 1.23.7 报出 8,717 次规则命中，模块 baseline 保存了 5,408 个唯一问题 ID。主要类别是 `MagicNumber` 4,411 个、`LongParameterList` 342 个、`LongMethod` 210 个和 `CyclomaticComplexMethod` 137 个。先前工作区里的 33 个额外问题 ID 单独跟踪。CI 的 Detekt 保持 `maxIssues: 0`，格式规则由 ktlint 负责。[审查进度与基线证据](code-review-progress.md#gradle-detekt-跟进)

## 实施顺序

| 批次 | 范围 | 处理与验收 |
| --- | --- | --- |
| 1 | Select、Toast、共享弹层 | 先处理能复现的状态覆盖、焦点和监听问题。清理经引用检查确认无用的私有代码。随后审查 `Select.kt` 和 `NovaToastViewport.kt` 的长函数，优先提取可独立验证的几何与决策逻辑。复测键盘、触屏、弹层关闭及焦点恢复。 |
| 2 | Slider、Sheet、Toggle、目录应用 | 复用现有主题 token，为行为阈值补齐语义和单位，从运行时读取平台数据。目录导航和滚动涉及已有工作区改动时，记录重叠位置，待整合后验证。按改动复测拖动、RTL、焦点以及浏览器前进后退。 |
| 3 | Questionnaire、DropdownMenu、Sidebar、Calendar 等热点 | 按文件审查职责和分支，优先处理私有实现与确有复用价值的规则。公开组件参数保持兼容。主题规范值、查找表、示例数据和测试期望值有明确来源时，记录保留理由。 |

## 全组件扩展

原三批为已实施批次。后续按组件源码包继续审查规则命中，包含跨平台实现和该组件的测试。仓库级扫描通过只能证明 baseline 外告警为零。每个组件仍需逐项查看可修复的存量问题，有依据地保留公开参数、主题值或测试数据，并在[逐组件进度](code-review-progress.md#全组件扩展进度)写明前后 ID、保留依据和验证。

## 每批验证与收尾

1. 按组件在隔离副本中工作，保留现有工作区改动。用 Detekt 1.23.7 和相同的配置、源码范围，为改动前后各生成一份临时问题 ID 清单。对比新增和消失的 ID，核对源码中的问题确实解决后，再从对应模块的正式 baseline 删除该批 ID。出现新 ID 时先检查新增告警或签名变化。
2. 运行受影响模块的 `detekt`、`ktlintCheck` 和相关 JVM 用例。缺陷修复须提供改动前复现和改动后通过的证据。视觉改动跑对应快照，Web 交互改动用真实浏览器验证。比对全量 JVM 时沿用已记录的四项基线失败及其断言。
3. 每批单独提交。在[审查进度](code-review-progress.md)记录文件位置、影响、删除的 ID、保留依据、提交和验证结果。每批结束时，新增 ID 为零，相关验证通过，保留公开 API、默认行为和主题差异。可修复项都有证据，待整合或有依据保留的项都已登记后结束清理。
